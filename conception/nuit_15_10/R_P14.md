## Lanceur : `tools/run_tests.py`
`python tools/run_tests.py [-j 4] [-r 3] [mot du test...]` (aussi `--reuse`, `--live`, `--skip`, `--snap`, `--timeout-x`).
- **Copie propre de HEAD** (dossier temporaire, `--snap`) : `robocopy /MIR` de `game/` (cache d'import et fichiers ignorés compris, dates conservées :
  pas de réimport complet, `--import` ensuite en ~ 1 min ; un `git archive` aurait demandé 10 min d'import et perdu les cerveaux hors git), puis les
  fichiers suivis modifiés sont remis à l'état de HEAD (`git show`) et les fichiers non suivis retirés. Le travail en cours des autres ne perturbe pas.
- **Un dossier utilisateur (APPDATA) par exécution**, supprimé ensuite : jamais le profil du joueur, aucun test n'hérite de l'état d'un autre.
- Parallèle limité (`-j`), délais par test (p4_activities 25 min, siège 15 min...), journaux par exécution, `rapport.json`.
- Verdict : code de sortie + lignes `ÉCHEC` / `Échecs : N>0` + erreurs de script. **COUPÉ** : code non nul sans aucune ligne d'échec (processus tué ou
  planté : au premier essai, 8 exécutions ont été coupées net, probablement un `taskkill` d'une autre session) -> relancé jusqu'à 2 fois avant d'être rouge.
- Tableau final : VERT / INSTABLE (X sur certaines exécutions) / ROUGE, avec le premier message d'échec ; sortie 0 si tout est vert.

## Pièges
- `--reuse` ne rafraîchit pas la copie : après une retouche, recopier le fichier ou relancer sans `--reuse`.
- Un test lancé à la main depuis l'éditeur lit le dossier utilisateur réel (mode dev compris) : seul le lanceur est reproductible.
- Bruit sans conséquence : avertissements d'UID des tenues (`tools/reparer_cache_uid.py`), `test_ideas` signale 2 erreurs `get_global_transform` (joueur hors arbre dans le test des potions).
- Au-delà de `-j 8`, la machine partagée manque de mémoire : préférer `-j 4` à `-j 6`.
